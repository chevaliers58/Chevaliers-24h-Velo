## Procédure VAPID (Windows, pour le responsable)
VAPID = paire de clés identifiant le serveur Web Push. Pas de nouveau compte ni de fournisseur payant nécessaire.
1. Dans [Supabase Edge Functions > Secrets](https://supabase.com/dashboard/project/qxlsdauqoivqhoojlrwk/functions/secrets), vérifier si VAPID_PUBLIC_KEY et VAPID_PRIVATE_KEY existent déjà. Si les deux existent, ne pas les remplacer (les abonnements actuels pourraient cesser de fonctionner). Si une seule est présente, demander une vérification avant de continuer.
2. Si les deux sont absentes, ouvrir le Terminal Windows / Invite de commandes sur un appareil de confiance. Si Node.js n'est pas installé, l'installer depuis https://nodejs.org/ (LTS). Vérifier avec `node -v` et `npm -v`.
3. Exécuter une seule fois : `npx --yes web-push@3.6.7 generate-vapid-keys`. Deux valeurs sont affichées. Copier chacune dans le champ correspondant, ne pas publier l'écran et ne pas envoyer les valeurs dans le chat.
4. Dans Secrets, ajouter ou vérifier les quatre entrées :
   - VAPID_PUBLIC_KEY : valeur Public Key générée.
   - VAPID_PRIVATE_KEY : valeur Private Key générée.
   - VAPID_SUBJECT : mailto:chevaliers58@gmail.com (adresse de contact, aucun mot de passe).
   - SITE_URL : https://chevaliers-24h-velo.pages.dev/velo (sans slash final ; vérifier l'ancienne valeur car d'autres fonctions peuvent l'utiliser).
   Enregistrer. Conserver la paire en lieu sûr et ne pas générer une nouvelle paire à chaque déploiement.
5. Informer le développeur que les quatre noms sont présents et que SITE_URL correspond au domaine. Ne communiquer aucune clé ni valeur privée. Le développeur vérifiera le correctif, déploiera app-notifications, testera l'origine Cloudflare et l'accès à la clé publique, vérifiera le cron puis l'activera de façon contrôlée (seul app-notifications-push). Le worker passe chaque minute quand actif. Ne pas activer les autres crons.
6. Sur le téléphone, ouvrir le site installé, se connecter, ouvrir Plus > Notifications / cloche > Activer les notifications et accepter l'autorisation. Sur iPhone/iPad iOS 16.4+ il faut d'abord ajouter le site à l'écran d'accueil, puis l'ouvrir depuis son icône. Sur Android, utiliser Chrome ou le site installé.
7. Tester une notification manuelle à un seul administrateur, application hors écran. Vérifier la cloche, le clic, la réception et l'arrivée sur la bonne page. Puis tester inscription/activité/collective/annulation avec comptes autorisés. Ne pas annoncer les push comme opérationnels avant essai réel.
8. Administration > Notifications : vérifier que les rappels dimanche et paliers correspondent au souhait du staff. Ne pas diffuser de données privées (lieux précis, GPX, identité de mineurs) par push.

Références : [web-push](https://github.com/web-push-libs/web-push#command-line), [secrets Supabase](https://supabase.com/docs/guides/functions/secrets), [Web Push iOS](https://webkit.org/blog/13878/). Guide général : [guide-github-staff.md](guide-github-staff.md).
